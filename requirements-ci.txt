# The ONE python dependency CI installs, pinned by content.
#
# verify_ceremony.py is stdlib-only because a client has to be able to run it,
# and it verifies ed25519 with libsodium when PyNaCl is importable and with its
# own implementation when it is not. Both paths are tested; CI installs PyNaCl so
# the vetted one is exercised rather than skipped past.
#
# By hash, because this job's purpose is to say which bytes a client's ceremony
# hash came from. An unpinned resolve runs installer code with write access to
# the workspace and to whatever the two suites that judge the validator import
# from.
#
# WHEELS ONLY, and therefore x86_64 linux on CPython 3.11 or 3.12 — the two
# interpreters our runners have (Debian bookworm ships 3.11, GitHub's
# ubuntu-latest ships 3.12). cffi publishes one wheel per interpreter, so a
# third Python has no pinned artifact here and pip must say so loudly. The
# sdists are deliberately NOT pinned: with them present pip answers an
# unsupported interpreter by compiling C in an image that has no compiler, which
# fails slowly and reads as an infrastructure fault rather than a missing pin.
# Adding an interpreter means adding its cffi wheel below.
#
# Regenerate with the sha256 digests PyPI publishes for each file:
#   python3 -c "import json,urllib.request; d=json.load(urllib.request.urlopen(
#     'https://pypi.org/pypi/<pkg>/<version>/json')); [print(f['filename'],
#     f['digests']['sha256']) for f in d['urls']]"
